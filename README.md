# Kanbano → Bitrix24 migrator

Набор скриптов для разовой миграции досок **Kanbano** в **Битрикс24**: выгрузка задач
с комментариями и вложениями, конвертация в CSV для штатного импорта задач и досылка
комментариев/файлов по REST API от имени оригинальных авторов.

## Состав

| Файл | Назначение |
|---|---|
| `kanbano_export.js` | Инжектируемый скрипт: выгружает доски/задачи/комментарии/вложения через внутреннее API Kanbano (запускается в браузере) |
| `kanbano_export.py` | Обёртка Playwright: headless Chrome с вашим профилем, запускает скрипт, скачивает файлы |
| `kanbano_json_to_csv.py` | Конвертер `kanbano_export.json` → CSV импорта задач Битрикс24 (проект — по тегу задачи) |
| `bitrix_followup.py` | Досылка комментариев и файлов в уже созданные задачи по REST API |
| `b24_client.py` | Минимальный клиент входящих вебхуков Битрикс24 (stdlib, пагинация, ретраи) |
| `probe_b24_files.py` | Диагностика: какой способ загрузки файлов работает на вашем портале |
| `tasks.csv` | Официальный шаблон CSV-импорта задач Битрикс24 (справка по колонкам) |

## Требования

- Python **3.10+**
- Пакет `playwright` и браузер Chromium:

```bash
pip install playwright
playwright install chromium
```

- Входящий вебхук Битрикс24 (права: `task`, `user`, `sonet_group`, `disk`) — нужен на шагах конвертации и досылки.

## Порядок миграции

### 1. Выгрузка из Kanbano

При первом запуске откройте окно браузера (`--headed`) и войдите в Kanbano — токен
сохранится в профиле `kanbano_chrome_profile/` и дальше хватит headless-режима.

```bash
python kanbano_export.py --headed          # первый вход
python kanbano_export.py --download-files  # выгрузка всех досок + файлов
```

Результат: `kanbano_export.json` (задачи, комментарии, метаданные вложений) и файлы
в `kanbano_files/<taskId>/`. Скрипт печатает предупреждение, если поле автора комментария
в API Kanbano не распознано — пришлите строку `extra: …` в issue.

Полезные флаги: `--board-ids 1,2` (выбор досок), `--include-archived-tasks`,
`--delay-ms` (пауза между запросами).

### 2. Конвертация в CSV

```bash
export B24_WEBHOOK="https://<портал>.bitrix24.ru/rest/<ID>/<КОД>/"
python kanbano_json_to_csv.py
```

Список проектов Битрикс24 загружается через вебхук (`sonet_group.get`) и кэшируется
в `bitrix_projects_cache.json`. Проект задачи определяется первым тегом, чьё имя
совпало с проектом (регистр/пробелы не важны); тег «Импорт» добавляется в колонку
«Теги» каждой задачи первым и проектом быть не может.

Офлайн-варианты: `--projects-file список_проектов.txt` (имя проекта на строку)
или уже существующий кэш. В конце — отчёт: теги без проекта и задачи с пустым
«Проект».

### 3. Импорт задач в Битрикс24

Импортируйте `tasks_import.csv` штатным мастером импорта задач (разделитель `;`,
кодировка utf-8). Рекомендуется сначала тестовый круг из нескольких задач.

### 4. Досылка комментариев и файлов

Скрипт находит созданные задачи по названию внутри проекта, переносит комментарии
(автор — по совпадению имени участника Kanbano с пользователем Битрикс24, email —
запасной способ) и прикрепляет файлы.

```bash
python bitrix_followup.py                 # dry-run: план без изменений
python bitrix_followup.py --apply         # выполнить
```

Идемпотентность: маркер `bitrix_followup_done.json` + сверка уже существующих
комментариев. Повторные запуски досылают только недостающее.

Дочёт режимов:

```bash
python bitrix_followup.py --attach-files-only --apply  # только файлы (комментарии уже есть)
python bitrix_followup.py --fix-authors --apply        # поправить авторов комментариев
python bitrix_followup.py --check-authors              # показать сопоставление авторов
```

### 5. Если что-то не вкладывается

```bash
python probe_b24_files.py
```

проверит на вашем портале, какой способ загрузки файлов работает, и напечатает ответы API.

## Как это работает

- **Комментарии** создаются через `task.commentitem.add` с `AUTHOR_ID`. Если участник
  Kanbano не сопоставился с пользователем Битрикс24 — комментарий уходит от владельца
  вебхука (все такие случаи в отчёте).
- **Файлы** комментариев не поддерживаются современным `task.commentitem.add`
  (`must not contain key "FILES"`), поэтому они загружаются на Диск
  (`disk.folder.uploadfile`) и прикрепляются к задаче (`tasks.task.file.attach`,
  фолбэк `UF_TASK_WEBDAV_FILES`). Загрузка выполняется от владельца вебхука —
  сменить автора файла REST API не позволяет; имена файлов на Диске уникализируются
  суффиксами, если в корне уже есть файл с таким именем.
- **События** (история изменений) Kanbano не переносятся — только комментарии.

## Ограничения

- Даты комментариев при пересоздании (в `--fix-authors`, если портал не принимает
  смену автора) становятся текущими — REST не позволяет создавать комментарии
  задним числом.
- Задачи без проекта (тег не совпал ни с одним проектом) импортируются, но
  комментарии к ним не досылаются — сопоставление задач идёт по названию внутри
  проекта. Перенесите такие задачи в проект и перезапустите `--apply`.
- Файлы в блоке «Файлы» задачи отображаются загруженными от владельца вебхука.
- Удалённые/архивированные задачи Kanbano не переносятся (архивные — опционально).

## Безопасность

- Вебхук передавайте только через переменную окружения `B24_WEBHOOK` или флаг
  `--webhook-url` — скрипты никогда не пишут его в файлы, кэш, CSV или логи.
- `kanbano_chrome_profile/` содержит ваш сеанс Kanbano (токены) — не публикуйте его.
  Все рабочие артефакты (`kanbano_export.json`, `kanbano_files/`, CSV, кэш, маркер)
  уже включены в `.gitignore`.

## Структура результатов работы

```
kanbano_export.json         выгрузка Kanbano
kanbano_files/<taskId>/     вложения задач
tasks_import.csv            CSV для импорта Битрикс24
bitrix_projects_cache.json  кэш списка проектов
bitrix_followup_done.json   маркер отправленных комментариев/файлов
```
